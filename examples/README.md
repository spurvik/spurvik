# Spurvik Runnable Examples (`examples/`)

> Source: https://github.com/spurvik/spurvik (`spurvik@1.0.4`, `spurvik-sdk@1.0.4`, `spurvik-mcp-server@1.0.2`).

| Example | What It Shows |
| --- | --- |
| [`multi-channel-hitl.ts`](./multi-channel-hitl.ts) | Pre-flight `ask_human()` fan-out with `createMultiChannelApprovalRouter` for Slack, Telegram, email (Resend), Discord, Microsoft Teams, Linear, Jira, Monday.com, and Asana. On `spurvik@1.0.4`, set `callbackBaseUrl` to your own endpoint (`https://your-app.example/api/spurvik/callback`). The handler there checks the link token with `verifyChannelApprovalToken`. `callbackBaseUrl` is optional in 1.0.4 and defaults to `https://console.spurvik.com/api/v1/hitl`, a console route that does not accept approver clicks. `callbackBaseUrl` is required from 1.0.5 (planned). Provenance records carry `inputHash`, a keyed HMAC-SHA256 fingerprint of the input. Keyed mode is the default and needs `contentHash.secret` of at least 16 characters. n8n execution history keeps node inputs and outputs. |
| [`slack-telegram-linear-ask-human/`](./slack-telegram-linear-ask-human/README.md) | Slack, Telegram, and Linear. Imports `createMultiChannelApprovalRouter` and `verifyChannelApprovalToken` from `spurvik`. `verifyChannelApprovalToken` checks Spurvik's approval-link token. Continues only when the queue status is `approved`. |
| [`nextjs-vercel-ai-sdk/`](./nextjs-vercel-ai-sdk/) | Next.js App Router chat with `<AIDisclosureLabel />` as an Art. 50(1) visible interaction notice and `spurvikMiddleware` recording a keyed HMAC-SHA256 fingerprint of the input. |
| [`n8n-make-import/`](./n8n-make-import/) | Import steps for **n8n** and **Make.com** against `n8n-nodes-spurvik@1.0.1`: workflow JSON using descriptor parameters `operation` and `systemName`, plus HTTP module settings. Make.com has no n8n community-node loader. |
| [`../packages/n8n-nodes-spurvik/make-com-blueprint.json`](../packages/n8n-nodes-spurvik/make-com-blueprint.json) | Make.com blueprint published with `n8n-nodes-spurvik@1.0.1`. The 1.0.1 tarball does not load as a native n8n node. Native node (planned, 1.0.2). Designed to support Article 12 record-keeping / Article 14 human oversight. |
